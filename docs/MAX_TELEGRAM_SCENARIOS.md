# Сценарии: пользователи MAX и Telegram

Проверка всех ситуаций, когда пользователь заходит через MAX или Telegram, и возможные проблемы при переходах между платформами.

---

## 1. Авторизация и учётная запись

### 1.1. Одна платформа

| Сценарий | Ожидание | Риск |
|----------|----------|------|
| Пользователь открывает приложение **в Telegram** → нажимает «Авторизация» | Сессия создаётся с `platform: "telegram"`, токен в localStorage контекста Telegram. Один User в БД (по `telegramId` из initData). | Нет. |
| Пользователь открывает приложение **в MAX** → нажимает «Авторизация» | Сессия создаётся с `platform: "max"`, токен в localStorage контекста MAX. Один User в БД (по `user.id` из initData MAX). | Нет. |

### 1.2. Разные платформы — один человек

| Сценарий | Что происходит | Проблема? |
|----------|----------------|-----------|
| Сначала авторизовался **в MAX**, потом открыл приложение **в Telegram** (тот же человек) | В Telegram другой контекст (другой iframe/браузер) → своего токена нет → снова запрос сессии с initData **Telegram**. Бэкенд создаёт/находит User по `telegramId` из **Telegram** initData. | **Да, возможны два аккаунта.** В MAX и в Telegram у пользователя разные `user.id`. В БД хранится один ключ — `telegramId` (но для MAX мы туда пишем id из MAX). Итого: один физический человек может получить два User (один с telegramId из Telegram, другой — из MAX), два набора профилей, две «личности». |
| Сначала авторизовался **в Telegram**, потом открыл **в MAX** | Аналогично: в MAX нет токена, новая сессия по initData MAX → отдельный User, если id в MAX другой. | Та же ситуация с двумя аккаунтами. |

**Вывод:** Пока бэкенд не связывает пользователя Telegram и пользователя MAX (например, по номеру телефона или явной привязке), один человек с двумя мессенджерами будет иметь два аккаунта. Это не ломает работу, но данные (профили, заявки) не объединяются.

## 2. Переход по ссылке «Связаться» / «Написать в Telegram»

| Кто смотрит | Кнопка | Куда ведёт ссылка | Проблема? |
|-------------|--------|--------------------|-----------|
| Пользователь **в Telegram** | «Написать в Telegram» | `https://t.me/<username>` | Нет. Открывается чат в Telegram. |
| Пользователь **в MAX** | «Связаться через MAX» | Та же ссылка `https://t.me/<username>` | **Нет технической ошибки**, но смысл другой: мы открываем **Telegram**, а не чат в MAX. Пользователь может не иметь Telegram или ожидать общения в MAX. |

**Важно:** Сейчас в профиле хранится только контакт для Telegram (`username` → `t.me/...`). Отдельной ссылки «чат в MAX» (диплинк MAX) в API нет, поэтому кнопка «Связаться через MAX» по сути ведёт в Telegram. Когда в API появится контакт для MAX (например, диплинк или id пользователя в MAX), ссылку для кнопки «Связаться через MAX» нужно будет подставлять отдельно.

**Открытие ссылки:** В Mini App (и Telegram, и MAX) ссылки контакта лучше открывать через `WebApp.openLink(url)`, чтобы хост-приложение сам открыл URL (внешний браузер или встроенный). Так не будет проблем с блокировкой popup и поведение будет предсказуемым.

## 3. Токен и переход между приложениями

| Сценарий | Результат |
|----------|------------|
| Закрыл приложение в MAX, открыл снова в MAX | Токен в localStorage MAX сохраняется → пользователь остаётся авторизованным (пока не истёк JWT). |
| Открыл тот же URL в **обычном браузере** (не Telegram, не MAX) | `isMiniApp` = false → токен из localStorage очищается (логика в `useTelegramAuth`). В браузере пользователь не авторизован. |
| Открыл в Telegram после того, как авторизовался в MAX | Токена в контексте Telegram нет (другое хранилище). Нужна повторная авторизация в Telegram → при разных id получится второй аккаунт (см. п. 1.2). |

Перенаправлений **на страницу входа Telegram или MAX** из нашего приложения нет: мы не делаем редирект на t.me или max.ru для авторизации. Единственный переход «вне приложения» — по кнопке контакта (`t.me/username`), и это не авторизация, а связь с другим пользователем.

## 4. Рекомендуемые проверки (ручное тестирование)

1. **Только Telegram**  
   Открыть приложение в Telegram → авторизация → лента, профиль, заявки, отклики, контакт «Написать в Telegram» на карточке → переход по ссылке открывает Telegram.

2. **Только MAX**  
   Открыть приложение в MAX → авторизация → те же экраны, на карточке «Связаться через MAX» → переход открывает ссылку (сейчас t.me) без ошибок.

3. **MAX → переход по t.me**  
   В MAX нажать «Связаться через MAX» → убедиться, что ссылка открывается (внешний браузер или клиент Telegram), приложение не падает.

4. **Браузер**  
   Открыть URL приложения в обычном браузере → не показывается кнопка «Авторизация» внизу, лента без токена, токен не сохраняется после «поддельного» ввода.

5. **Истечение сессии**  
   В Telegram или MAX после истечения JWT при запросе API приходит 401 → фронт очищает токен и показывает состояние «гостя»; при повторном открытии Mini App нужна новая авторизация.

---

## 5. Чек-лист для ручной проверки

Перед релизом имеет смысл пройти сценарии:

- [ ] **Только Telegram:** открыть приложение в Telegram → авторизация → лента, профиль, заявки, отклики → на карточке профиля/объявления/отклика кнопка «Написать в Telegram» → клик открывает чат (через WebApp.openLink).
- [ ] **Только MAX:** открыть приложение в MAX → авторизация → те же экраны → на карточке «Связаться через MAX» → клик открывает ссылку (сейчас t.me) без ошибок.
- [ ] **MAX → клик по контакту:** в MAX нажать «Связаться через MAX» → ссылка открывается во внешнем браузере/клиенте, приложение не падает.
- [ ] **Браузер:** открыть URL в обычном браузере → кнопки «Авторизация» внизу нет, лента без токена, контакт — обычная ссылка `<a href="...">`.
- [ ] **401:** в Mini App дождаться истечения JWT или подставить неверный токен → при запросе 401 → фронт очищает токен, показывается состояние гостя.

## 6. Что доработано

- **Один пользователь — Telegram и MAX:** реализовано. В БД у User добавлены `max_id` (для входа через MAX) и опциональный `telegram_id`. Сессия создаётся по `telegram_id` для Telegram и по `max_id` для MAX. Привязка: в MAX пользователь нажимает «Получить код привязки» (профиль), вызывается `POST /me/link-telegram-request`, показывается код. Пользователь в Telegram отправляет боту команду `/start <код>`. **Бот при получении `/start <код>` должен вызвать `POST /link/redeem`** с телом `{ "code": "<код>", "telegramId": <id из update.message.from.id> }` и заголовком `Authorization: Bearer <BOT_TOKEN>`. После успешного ответа один User имеет и `telegram_id`, и `max_id` — один аккаунт в обоих клиентах.
- **Контакт в MAX:** реализовано. В User добавлено поле `max_profile_url`. В профиле (редактирование) можно указать «Ссылка на профиль в MAX». В карточке и в откликах при `platform === "max"` кнопка «Связаться через MAX» открывает эту ссылку (если задана), иначе — t.me.
- **Открытие ссылок в Mini App:** реализовано. Везде, где показывается контакт (профиль, объявление, отклики), по клику вызывается `openContactUrl(url)`: в Mini App используется `WebApp.openLink(url)` (Telegram или MAX), в браузере — `window.open`.
