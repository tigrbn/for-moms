# Проверка сохранения профиля и обновление БД

## Где какие поля хранятся в БД

| Поле (форма)           | Таблица            | Колонка           |
|------------------------|--------------------|-------------------|
| Имя для отображения    | `profiles`         | `display_name`    |
| Возраст                | `profiles`         | `age`             |
| Город                  | `profiles`         | `city`            |
| Район                  | `profiles`         | `district`        |
| Возраст детей          | `parent_profiles`  | `children_ages` (JSON массив чисел) |
| Пожелания              | `parent_profiles`  | `special_wishes`  |
| Категория (специалист) | `specialist_profiles` | `skills` (JSON массив строк, напр. `["Няня"]`) |
| Цена за час            | `specialist_profiles` | `price_per_hour` |
| О себе                 | `specialist_profiles` | `about`        |

Для родителя: запись в `profiles` (id профиля) + запись в `parent_profiles` (profile_id = id профиля).  
Для специалиста: запись в `profiles` + запись в `specialist_profiles` (profile_id = id профиля).

---

## Что уже есть в коде (проверено)

### Нижнее меню
- Раздел **«Роли»** в нижнем меню **уже убран**. В навигации только: Лента, Профиль, Создать, Все заявки.

### Страница «Профиль»

**Родитель:**
- Имя, Возраст, Город → сохраняются в таблицу `profiles` (поля `display_name`, `age`, `city`).
- Возраст детей, Пожелания → сохраняются в таблицу `parent_profiles` (поля `children_ages`, `special_wishes`).

**Специалист:**
- Имя, Возраст, Город → в `profiles`.
- Категория (Няня / Репетитор / Досуг) → в `specialist_profiles.skills` (по ней фильтруется лента родителя).
- Цена за час, О себе → в `specialist_profiles` (`price_per_hour`, `about`).

### Бэкенд
- `PATCH /profiles/:id` — обновляет `displayName`, `age`, `city`.
- `PATCH /profiles/:id/parent` — обновляет `childrenAges`, `specialWishes`.
- `PATCH /profiles/:id/specialist` — обновляет `skills` (категория), `pricePerHour`, `about`.

## Почему данные могут не сохраняться

Если в базе **нет колонки `age`** в таблице `profiles`, то при сохранении возраста запрос к БД падает и данные не записываются. Остальные поля (имя, город, возраст детей, пожелания, цена, о себе, категория) тоже могут не сохраняться, если миграции не применены и структура БД не совпадает со схемой.

## Почему на странице «Профиль» не отображаются сохранённые поля (имя и город есть, остальное — нет)

Страница заполняет форму из ответа **GET /me**. Если на сервере не были применены миграции из каталога **api** (см. ниже), то в БД нет колонки `age` и связанных таблиц/полей в актуальном виде, и API в ответе /me отдаёт для этих полей `null`. В результате форма при открытии раздела и после сохранения показывает только то, что пришло в /me (имя, город), а возраст, возраст детей, пожелания, цена, о себе — пустые. **Решение:** выполнить на сервере `npx prisma migrate deploy` и `npx prisma generate` из каталога **api**, затем перезапустить API.

---

## Что обязательно сделать на сервере (обновить БД)

**Важно:** миграции нужно запускать из каталога **api** (там лежит `prisma/schema.prisma`). Из каталога `web` команда `npx prisma migrate deploy` выдаст ошибку «schema.prisma: file not found».

На сервере (например, если проект в `/root/formoms`):

```bash
cd /root/formoms/api
npx prisma migrate deploy
npx prisma generate
pm2 restart all
```

- **`prisma migrate deploy`** — применяет все неприменённые миграции:
  - добавляет колонку `age` в `profiles` (если её ещё нет);
  - при наличии миграции `20260208120000_add_age_drop_shop` — удаляет таблицы магазина.
- **`prisma generate`** — обновляет Prisma Client под текущую схему.

После этого перезапустите API (например `pm2 restart` или как у вас настроено).

## Как проверить, что БД обновлена

В PostgreSQL выполните:

```sql
-- Должна быть колонка age в profiles
SELECT column_name FROM information_schema.columns
WHERE table_name = 'profiles' AND column_name = 'age';
-- Должна вернуться одна строка: age

-- Таблицы магазина должны отсутствовать (если применялась миграция drop shop)
SELECT table_name FROM information_schema.tables
WHERE table_schema = 'public' AND table_name LIKE 'shop%';
-- Должно быть пусто (или только старые таблицы, если миграция ещё не применялась)
```

После применения миграций и перезапуска API все перечисленные поля профиля (включая возраст, возраст детей, пожелания, цену, о себе, категорию) должны сохраняться в БД.

## Логи (что добавлено для отладки)

**Сервер (API):** при каждом сохранении профиля в логах NestJS появятся строки:
- `PATCH /profiles/:id (base) body=...` — что пришло в теле запроса (имя, возраст, город).
- `updateBase profileId=... data keys=... updateData=...` — какие поля реально уходят в Prisma.
- `PATCH /profiles/:id (base) result age=...` — что вернула БД после обновления.
- Аналогично для `.../parent` и `.../specialist`.

Смотреть логи: вывод процесса API (например `pm2 logs` или вывод в консоли при `npm run start:dev`).

**Браузер:** откройте DevTools (F12) → вкладка Console. При нажатии «Сохранить» появятся:
- `[Profile] PATCH /profiles/X (base) {...}` — что отправляется на сервер.
- `[Profile] PATCH /profiles/X/parent` или `.../specialist` — то же для родителя/специалиста.
- При ошибке: `[Profile] save error ...`.

Если в логах сервера `body={}` или `updateData={}`, значит запрос пришёл без полей (проверьте URL и прокси). Если в браузере в логе видно `age: 25`, а на сервере `body={"displayName":"Мария","city":"Якутск"}` без age — значит по пути (прокси, middleware) поле теряется.

**Если в таблице `profiles` колонка `age` всегда NULL**, а в запросе вы отправляете возраст: на сервере после миграций обязательно выполните `npx prisma generate` и перезапустите API. Иначе старый Prisma Client не знает о поле `age` и не записывает его в БД.
